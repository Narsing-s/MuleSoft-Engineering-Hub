# Publication content guidelines

## Publishing model
MuleSoft Engineering Hub is owner-managed. Only the configured publication owner can create, edit, publish, unpublish or delete articles. Readers can access published content without an account.

## Editorial standards
- Explain the problem before introducing a solution.
- Use beginner-friendly steps and define unfamiliar terms.
- Prefer realistic synthetic examples over generic theory.
- Include Mule 4/DataWeave examples and state assumptions.
- Mention runtime and connector version differences when relevant.
- Include failure handling, security, observability and testing guidance.
- Add an architecture diagram when it clarifies a flow.
- End with a checklist, exercise or interview checkpoint.
- Review spelling, code formatting, links and accessibility text before publishing.

## Security and confidentiality
Never publish credentials, access tokens, private keys, customer data, production payloads, internal hostnames, client names or proprietary diagrams. Use fake domains and synthetic data. Do not copy confidential employer/client documentation.

## Corrections
If an example is wrong or becomes outdated, update the article promptly and add a short correction note when readers may have relied on the old guidance.

## Independence
MuleSoft Engineering Hub is an independent learning publication and is not an official Salesforce or MuleSoft publication unless a formal relationship is separately established.
